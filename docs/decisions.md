# Decisions

Settled; change only with a new entry that says why.

1. **Name** (superseded by 28): Fleet. "Shoal" in the design is replaced everywhere.
2. **UI stack**: `gpui-component` 0.7.x on `gpui-pre` (a published snapshot of Zed's gpui main). The
   crates.io `gpui` 0.2.2 is a year old; a git dependency on Zed would not combine with the
   component kit.
3. **Visual source of truth**: v2 screens. v1 screens provide content for pages v2 links to but does not
   draw, restyled to v2 rules (no cards, no pills, 3px radii, rules between sections).
4. **Kubernetes client**: kube-rs 4.x + k8s-openapi 0.28 on tokio, isolated in `flock-kube` behind
   async channels.
5. **Flux types**: generated with kopium from the CRDs of the Flux release pinned in `mise.toml`,
   committed, regenerated by `mise run gen:flux`.
6. **Git history for Changes**: system `git` with the user's own credentials into a cache under
   `~/Library/Caches/dev.flock.app/git`. Flux secrets are never read for git auth.
7. **Helm history**: decoded from `sh.helm.release.v1.*` secrets client-side.
8. **Exec auth on macOS**: capture the login-shell environment once at startup (timeout, fallback
   PATH list) so `aws`, `doctl`, `gke-gcloud-auth-plugin` resolve when launched from Finder.
9. **Loco**: cargo feature `loco`, off by default. Raw `resource-<uuid>` / `ws-<id>` names in v1.
10. **Writes**: full actions as designed; destructive ones confirm in-app.
11. **Demo mode**: the design's sample data is a real backend (`flock-demo`); parity screenshots use it.
12. **License**: Apache-2.0.
13. **PRs**: one unit per PR, merged immediately by the orchestrator.
14. **No hotbar**: v2 has no hotbar, so Cluster settings drops v1's Pin column and `Show in hotbar`
    toggle. The cluster switcher lists every cluster (decision 18).
15. **What counts as destructive**: cordon and uncordon only toggle scheduling, evict nothing and
    undo in one click, so they run at once. Drain (evicts pods), delete and apply-from-compare are
    destructive and confirm in-app unless the cluster's "Confirm destructive actions" setting is
    off.
16. **Collapsed strips are useful, not decorative** (superseded by 18): deviates from HANDOFF's "vertical label",
    requested by the product owner. The clusters strip (28px) shows the expand chevron, an "All
    clusters" glyph row, then one status-glyph row per cluster (selected marked with `sel`, tooltip
    `name · state`, click selects). The resources strip shows the chevron and one glyph-over-count
    row per nav entry that has problems (worst status first, tooltip = entry name, click
    navigates); with no problems it is the chevron alone. `kit::VerticalLabel` and `ttf-parser` are
    removed.
17. **Multiple windows** (split deferral superseded by 30): one backend and one UI Store distribute snapshots to every window;
    each shell owns its navigation, screens, focus and streams. Backend navigation commands carry
    the shell entity id so page watches, YAML, workload streams and Flux details stay independent
    until that window closes; connections and the backend runtime remain shared. ⌥↵ opens a palette
    navigation result in another window, ⌘N opens Flock home, and ⌘W closes the current window. Flock quits only when
    the last window closes, matching gpui's close-window example rather than remaining headless.
    Palette mutations and panel toggles run only in the current window. Split navigation is deferred:
    the shell owns screen entities, dialogs, subscriptions and focus alongside selection; the kit's
    Split primitive divides layout but does not isolate those owners. A follow-up must extract pane
    ownership before adding independent navigation and focused-pane close behavior.
18. **One sidebar; clusters switch from the status bar**: requested by the product owner
    (#110, #111, #121); supersedes HANDOFF's two-panel layout and decision 16. The window has one
    left sidebar: the 28px top strip (traffic lights, collapse chevron), then the nav for the
    current scope, Flock home's Overview / Problems / GitOps / Changes or the cluster's pages. ⌘B
    collapses it to 76px, just the strip and an expand chevron, with no cluster name or state.
    The clusters panel, both strips and ⌘⇧B are gone. The status bar starts with the cluster
    switcher (status glyph and name, or ◎ All clusters); a click or ⌘⇧C opens a popover above it
    with All clusters, every cluster (glyph, state, problem counts) and Add cluster. Typing
    filters, ↑ ↓ ↵ pick, ⌘. or the row's ⋯ opens that cluster's actions (Settings, Connect or
    Disconnect, Remove from Flock). Selecting a cluster only moves navigation; every added
    cluster stays connected. The LOCO section shows only on clusters where `infra.loco.io` is
    detected. Inspectors (nodes, pods, resources, workload) slide and fade in and out
    (`theme::INSPECTOR_IN`, `INSPECTOR_OUT`, `INSPECTOR_SWAP`, ease-out) only when they open or
    close; selecting another row while one is open swaps the content in place.
19. **App settings** (#112): `flock_core::AppSettings` is the one model (theme, refresh presets,
    notifications), saved as `settings.json` in the Flock data dir with the same set-aside handling
    as `clusters.json`. The app owns the file; the UI holds the live value in a global and applies
    the theme to every window at once. Refresh presets reach the live backend as
    `Command::SetRefresh` and retime its polling and snapshot tickers without a restart; watches
    are never polled. New problems post a macOS notification once per resource (errors by default,
    warnings on request); a problem that returns within `notify::COOLDOWN` or appears during a
    cluster's first `CONNECT_GRACE` stays quiet, and a cluster's "Notify about new problems"
    preference mutes it. Notifications need the app bundle; unbundled builds say so on the page.
20. **Keyboard** (#114): one binding table, `flock_ui::keymap::BINDINGS`, binds every key, draws
    the Keyboard shortcuts section of Settings and generates `docs/keyboard.md` (`mise run
    gen:keys`; a test fails when the file is stale). VS Code bindings where they map: ⌘P quick open,
    ⌘⇧P the palette in `>` mode, ⌘B sidebar, ⌘J dock, ⌘, settings, ⌃Tab / ⌃⇧Tab recent pages,
    ⌘[ / ⌘] history, / or ⌘F the page filter; ⌘K stays. ⌘W now closes the inspector, then the
    dock, then the window (amends 17). History and the recent-page cycle live in
    `flock_core::history`; a page restored from history replays the commands that reach it.
    A list's inspected object (`Location::inspecting`, #281) belongs to the current history entry:
    inspecting or closing a row amends that entry instead of adding one, so Back reopens the inspector.
    ⌘1 focuses the sidebar (arrows move a focus ring, Enter opens), ⌘2 the page's main list,
    and Tab / ⇧Tab walk gpui's tab stops. After any navigation the shell takes keyboard focus
    back so keys keep working when the focused list disappears.
21. **Namespaced lists start in one namespace** (#117, #131; the scoped watches are superseded by
    32): pods, events and every resource list (Deployments through PVCs) open in the cluster's
    default namespace: the cluster settings override, else the kubeconfig context's namespace, else
    `default`. "All namespaces" is an explicit pick. The one store is the cluster's
    `Preferences::namespaces`, keyed by list (`flock_core::resources::namespaced_list`: `Pod`,
    `Event`, the resource kind's name), saved with the other cluster preferences in `clusters.json`
    through `Command::SetPreferences`. The live backend reads the same preference when it subscribes
    a page and runs that page's reflector for the one namespace (`WatchKey` = kind + namespace),
    plus the cluster-wide Namespace list for the picker. A preference change resubscribes every
    window. Sidebar counts come only from cluster-wide watches, so a scoped list shows no count
    instead of a partial one. Pods stay on the always-on cluster-wide pod watch that problem
    detection needs, so for pods only the view is scoped.
22. **No summary sentence on list pages; actions live on rows** (#119, #120): requested by the
    product owner; supersedes HANDOFF's "one plain sentence first" for list pages (Cluster overview,
    Nodes, Namespaces, Events, Pods and every resource list), which now open on the FilterBar. The
    overview and Nodes keep their mono meta line (`kit::MetaLine`). Object pages keep their
    sentence where it says something nothing else does: the pod inspector's container state,
    Compare. (The Flux object status and the workload rollout sentences were replaced by the
    raw condition line in 46.) Object actions move off inspector
    headers onto the rows themselves: every row with actions shows a ⋯ on hover and opens the same
    menu on right-click (`Table::row_actions`), with one-line descriptions and the usual in-app
    confirm for destructive items (decision 15). Inspectors keep only their primary action (Cordon
    or Uncordon, Shell) and close. Page headers keep one primary action plus their Actions menu
    (workload, Flux object). The non-functional ⋯ on list page headers is gone.
23. **Pane tabs** (design v3; product owner): supersedes HANDOFF's "No tabs" and amends 17 and
    20. `flock_core::AppState` owns `flock_core::tabs::Panes`: a list of panes (one until Split
    lands), each with its own tabs and active tab, and each tab with its own `Location` (cluster,
    page, selected object, log container) and its own `History` for ⌘[ / ⌘]. Navigation commands
    move the active tab of the focused pane; the sidebar and the status-bar switcher follow that
    tab's cluster. VS Code semantics: a sidebar click or row open navigates the active tab;
    ⌘-click, middle-click, ⌘↵ in the palette and the row menus' "Open in new tab" open a tab
    beside it (`Command::NewTab`), focusing an existing tab with the same location instead of
    duplicating it. ⌘T opens Flock home in a new tab; ⌘W closes the active tab and closing the window's
    last tab closes the window (product owner, 2026-10-19; it used to leave Flock home). ⌃Tab / ⌃⇧Tab and
    ⌥⌘→ / ⌥⌘← cycle tabs in strip order (the recent-page cycle is gone), ⌘1…⌘9 select tab N;
    middle-click closes a tab and dragging reorders it. The old focus bindings move from ⌘1 / ⌘2
    to ⌘⇧E (sidebar) and ⌘E (page list), and the workload terminal from ⌘T to ⌃`. A tab is
    labelled with the object's status glyph, a kind (none for Flock home pages, so they read "Overview", the kubectl
    short kind for objects, `logs` with the pod's hash suffix, `loco` / `workloads` / `flux` /
    `network` / `config` / `storage` from the nav section, `cluster` for the rest), the name, and
    the cluster's short name (`tabs::short_name`: a leading segment shared with another cluster is
    dropped when the rest stays unique). The strip scrolls horizontally and keeps the active tab
    in view. The Workload dock stays; "Open logs in tab" opens the selected pod's logs as a tab.
    A cluster that leaves the snapshot no longer resets its tabs to Flock home.
24. **Two highlight colours, not themes**: requested by the product owner instead of a theme
    registry. Flock Dark and Flock Light stay the only token sets (HANDOFF's table). Settings →
    Appearance has a Primary highlight (the accent family: `acc`, `onacc`, `focus`, `accbg`; links,
    primary buttons, the focus ring, the active tab line) and a Secondary highlight (the selection
    family: `sel`, `selfg`, `selline`). Each is a preset (Blue, Purple, Teal, Green, Orange, Pink,
    Graphite) or a custom `#rrggbb`, saved in `AppSettings` (`primary`, `secondary`). Blue is the
    HANDOFF tokens unchanged. Any other choice keeps only its hue and saturation and
    `flock_ui::highlight::apply` derives the dark and light variants, stepping lightness until
    accent text is ≥ 4.5:1 on `editor`, `panel` and its own tint, `onacc` is ≥ 4.5:1 on `acc`,
    and `selfg`, `fg`, `fg2`, `mute` are ≥ 4.5:1 and status glyphs ≥ 3:1 on `sel`. The override
    applies to every window at once and to the gpui-component kit theme.
25. **v3 sidebar and status-bar switcher** (design v3; product owner; collapse chevron, expand chevron and width superseded by 52): supersedes the parts of 16
    and 18 that conflict. The sidebar is 200px: the 28px strip (traffic lights only), then a 32px
    header with the scope (All clusters, or the active tab's cluster) and the ⌘B collapse
    chevron, then the nav. Collapsed it is 0px wide (52): the product owner
    overrides the design's vertical scope label, so `kit::VerticalLabel` stays removed. The cluster
    switcher moves from the start of the status bar to its right end, after a 1px rule; the
    problem counts come first and the scope facts ellipsize. Its menu is 290px, anchored to the
    right edge above the bar: All clusters (⌘0, a new binding that also works with the menu
    closed), a rule, every cluster (glyph, name, problem counts, or the state when it is not
    healthy, offline names in mute), a rule, Add cluster…. The current row uses `sel`; the hovered
    and the current row show a gear that opens Cluster settings. The query field and footer are
    gone: ↑ ↓ ↵ Esc and type-ahead letters move and pick. Connect or Disconnect and Remove from
    Flock move to right-click on a cluster row (or ⌘. on the highlighted one), which shows the
    same Settings / Connect or Disconnect / Remove list as before, and stay in Cluster settings.
    Picking a cluster retargets the active tab (decision 23) to the same page on that cluster,
    or the same object when it exists there, else that cluster's Overview; All clusters retargets
    it to Flock home. The move is one history step, so ⌘[ returns to the previous cluster.
26. **Self-update from GitHub Releases** (#157 and the updater PR): `flock-update` owns checking,
    downloading, verifying and installing; the UI talks to it only through `flock_core::updater`
    (`UpdaterRequest`, `UpdaterStatus`) and schedules checks itself (20 s after launch, then every
    1, 6 or 24 hours; on by default; pre-releases opt-in). An update is installed only after its
    ed25519 signature (key compiled in, `flock_update::signature::PUBLIC_KEY`) and SHA-256 both
    match; it is unzipped with `ditto` into `.flock-update` beside the running bundle, its
    `CFBundleIdentifier` and version are checked against the release, the quarantine attribute is
    stripped and `codesign --verify` must pass. "Restart to update" moves the running bundle to
    `.flock-previous.app`, moves the staged one in (moving the old one back if that fails),
    relaunches with `open -n` and quits; the next launch removes both leftovers. A copy that is not
    a bundle (`cargo run`) or sits in a folder Flock cannot write (App Translocation, a read-only
    volume) links to the release page instead. Releases are arm64 only, assets
    `Flock-<version>-arm64.zip` and `Flock-<version>-loco-arm64.zip` (`--features loco`), each with
    `.sha256` and `.sig`; a build updates only from its own variant.
27. **Tabs persist per window** (product owner): every window's panes and tabs (their locations,
    not their history) are saved as `tabs.json` in the Flock data dir with the same set-aside
    handling as `settings.json` (`flock_kube::tab_store::TabStore`, a toast names the kept file).
    The UI keeps one entry per open window in open order (`flock_ui::session`) and saves on every
    tab change; closing a window drops its entry unless it was the last one, so quitting by closing
    the last window or with ⌘Q restores everything. A plain launch reopens one window per saved
    entry; `--demo`, `--screen` other than flock and an empty file open the usual startup window.
    A tab whose Flux object has not loaded yet waits for it, and a tab whose cluster is no longer
    in Flock says so and offers "Show all clusters". Unknown pages (a Loco tab read by a build
    without Loco) are dropped one tab at a time instead of discarding the file.
28. **Name: Flock** (product owner; supersedes 1): the product is Flock, a flock of sheep, matching
    the sheep icon. The rename lands once, before the first release: crates and apps are
    `flock-*`, the binary `flock`, the bundle `Flock.app` with identifier `dev.flock.app`,
    environment variables `FLOCK_*`, and the repository `team-loco/flock-app` (the updater reads
    it from `Cargo.toml`). "Shoal" and "Fleet" in the design are replaced with Flock everywhere.
    On launch with the default data dir, `~/Library/Application Support/dev.fleet.app` and
    `~/Library/Caches/dev.fleet.app` move to `dev.flock.app` when the new folder does not exist
    yet: a rename, or a copy that leaves the old folder in place when the rename fails
    (`flock_kube::migrate`). Sample data keeps the Flux convention repo name `fleet-infra`, and the
    kind scenario clusters stay `fleet-a` and `fleet-b`.
29. **One title row; the collapsed sidebar is hidden** (#165, product owner; supersedes the strip and
    collapsed width in 25): the sidebar's top strip and the pane tab strip are one 32px title row
    (`theme::TITLE_ROW`, the design's tab strip height; the 44px page header sits below the tab
    strip, so it never shares a row with the lights). The traffic lights are centred in it
    (`TRAFFIC_LIGHT_X` 10px, `TRAFFIC_LIGHT_Y` 9px) and never move. ⌘B collapses the sidebar to 0px;
    the first pane's tab strip then starts with the window controls: `TRAFFIC_LIGHTS_INSET` (78px,
    the 60px measured span of the three lights from x 10 plus 8px) of empty, draggable row. The controls' width animates with the sidebar's, so tabs never pass under the
    lights. Empty parts of the title row drag the window in both states.
30. **Split right** (#77, design v3 `Split` and `PaneTabs`; product owner; supersedes the split
    deferral in 17): ⌘\ or the 32px Split right button at the end of a pane's tab strip opens the
    active tab in a second pane on the right; with two panes it opens it in the other pane instead,
    since a window has at most two side-by-side panes (`tabs::MAX_PANES`, no vertical split). Each
    pane has its own tabs, active tab, screens (`shell::pane::PaneScreens`) and backend scope: every
    pane navigates the backend under its own `Command::ForWindow` id from a process-wide counter and
    sends `Command::WindowClosed` for it when the pane or window closes, so page watches, YAML,
    workload streams and Flux details stay independent per pane. A click anywhere in a pane focuses
    it, ⌥⌘1 / ⌥⌘2 focus pane 1 or 2, and navigation from a pane's own screens focuses that pane
    first; background commands from a screen (watch and stream requests) reach its pane's scope
    without moving focus. The sidebar, status-bar switcher, palette and ⌘W follow the focused pane;
    only the focused pane's active tab has the `acc` bottom line. Closing a pane's last tab closes the
    pane; the window's last tab closes the window. A split keeps each pane's
    inspector as it was: the existing pane is not re-revealed, and the new pane opens the inspector
    only if the source pane had it open. Tabs move to the other pane from the
    tab's right-click menu (Move to the other pane, or Move to a split on the right when unsplit)
    or by dropping them on the other pane's strip. ⌘⇧↵ in the palette opens the result in a split
    (⌘↵ stays new tab, ⌥↵ new window). The 1px `line2` divider drags; its share
    (`tabs::Divider`, thousandths, kept between 10% and 90%) is saved with the window's panes in
    `tabs.json`. A split pane shows compact views: a workload shows its header, sentence, key
    fields (`Workload::fields`) and pods; a Flux object its status block; logs only the lines. The
    first two end with "Open full view →", which joins both panes into one with that tab active, so
    no tab is lost. Every other page renders its full page.
31. **Every nav kind is watched in the background** (#177, product owner; amends 21): from connect to
    disconnect every connected cluster runs one cluster-wide watch per kind the sidebar shows
    (`snapshot::BACKGROUND_KINDS`: nodes, namespaces, events, pods, the five workload kinds,
    services, ingresses, ConfigMaps, Secrets, PVCs), the Flux kinds where Flux is served and the
    Loco kinds on every cluster where `infra.loco.io` is detected, whatever page is open. Sidebar
    counts and error and warning badges for every cluster come from these stores on every snapshot,
    through status-only helpers the list rows share (`lists::counts`), and a kind shows a count once
    its watch has synced. ConfigMaps and Secrets stay metadata-only and every store drops
    `managedFields` and the last-applied annotation; workloads, services and PVCs keep spec and
    status because their rows, their health, Compare and the workload page read them. Events keep
    only the newest `KubeSettings::event_limit` per cluster (`resources::EventWindow`), the same
    window the Events page lists. ReplicaSets, YAML, Helm history, logs and workload history stay
    on demand.
32. **Pages read the background stores; the namespace picker filters** (#177, #178, product owner;
    supersedes the namespace-scoped watches in 21 and the #145 / #152 plumbing): a page no longer
    subscribes its own watch, so `WatchKey`, `subscribe_in`, `page_watches` and the per-page
    subscriptions are gone. Pods, Events and every resource list read the cluster-wide store of
    decision 31, and the namespace picker (still one preference per cluster and list, still opening
    on the default namespace) filters rows in the UI. One long-lived watch per kind is cheap for
    the API server: an idle watch costs it a connection and nothing per object, while the old
    scoped watches started a fresh list and watch on every page or namespace change. Filtering a
    local store takes microseconds and makes switching namespace instant. A watch that fails after
    its first sync reports `WatchState::Refreshing` and the page keeps its rows; `Pending` (skeleton)
    is reserved for data that never loaded. `AppState` keeps a connected cluster's last detail and
    pod rows until a snapshot rebuilds them, so returning to a tab, pane or cluster renders what was
    in memory at once and the next snapshot refreshes it.
33. **Suspended Flux objects lead with Resume** (#202; amends HANDOFF's "for example Reconcile"):
    Reconcile cannot run on a suspended object, so the Flux object page's one primary action is
    Resume while the object is suspended and Reconcile otherwise. The Actions menu keeps Suspend /
    Resume as before, and ⌘R stays Reconcile.
34. **Short cluster names drop only a shared environment prefix** (#203; amends 23): `tabs::short_name`
    drops a leading segment only when it is an environment word (`prod`, `staging`, `dev`, `qa`,
    `test`, `uat` and their spellings), another cluster shares it, and the rest has at least three
    characters and names no other cluster. `prod-us-east` / `prod-eu-west` become `us-east` /
    `eu-west`; `fleet-a` / `fleet-b` keep their whole names. Tabs, Compare and the Changes lane
    headers all use it, and Changes lane columns widen to fit the name.
35. **Merged pod logs** (#230, product owner): `Command::FollowLogs(LogTarget)` opens a `Logs <target>`
    tab that streams every matching pod and container at once, stern-style. A target is a workload
    (any controller kind, Jobs included, matched by the pod's controlling owner), a label selector
    in a namespace (from a Pods label filter) or the pods ⇧-clicked on the Pods page. The backend
    (`flock_kube::actions::multi_logs`) reads the always-on pod store every second: started
    containers join, deleted pods leave, a restarted container is followed again, and at most
    `MAX_STREAMS` log requests run at once per view. The UI merges lines by their RFC 3339
    timestamp into a buffer of `MERGED_LINES` and colours each pod from a palette derived from the
    theme. Entry points: the workload Actions menu (Logs for all pods), the workload dock's
    `All pods` menu item, the Pods row menu (⇧-click rows or apply a label filter, then Logs for N selected pods or Logs for <selector>) and the
    palette's `Logs: follow all <workload> pods`, which opened the workload page before.
36. **Edit YAML applies server-side, pinned to what the user saw** (#231): every object opens in an
    Edit YAML tab (row menus, inspectors, ⌘E while YAML shows). The editable text drops `status`,
    `managedFields`, server metadata and the last-applied annotation, and stays redacted unless the
    user reveals a Secret's values (one confirm, the tab reloads). Review runs a dry-run
    server-side apply as field manager `flock` and diffs live against its result; Apply asks to
    confirm when the cluster confirms destructive actions. Both force field ownership, so the dry
    run shows exactly what Apply writes, and both pin `metadata.uid` and
    `metadata.resourceVersion`: a changed or recreated object is a conflict that shows what moved
    and offers the edit rebased onto the new object (a field-level three-way merge; where both
    sides changed a field the edit wins and is named). Redacted values the user left alone are
    restored from the live object before sending; a mask that is typed or partly kept is refused,
    so a placeholder is never written back. A newer resourceVersion whose editable text is unchanged
    (a controller only touched `status` or server metadata) is not a conflict: the edit is pinned to
    the new version and sent.
37. **Unhealthy rows say why; inspectors lead with what's wrong** (#239, product owner): every
    resource list, Pods, Nodes and the Flux lists carry a Reason column (Pods: Message, since their
    Status column already shows the reason) filled only for Err and Warn rows and truncated with
    the full text in a tooltip and the inspector. The reason is derived outside the view:
    `flock_core::diagnosis` holds one `Condition` type for every kind (it replaced the pod and node
    condition types) with its polarity (`Failed`, `Stalled`, pressure and similar types are bad when
    True, `Reconciling` is progress, `Suspended` is neutral), picks the first of the worst
    conditions, names nodes `NotReady` or the pressure type, and keeps PVCs `Pending` with the
    newest warning event as the message. Workload rows prefer their pods' worst issue
    (CrashLoopBackOff, ImagePullBackOff, last exit OOMKilled) over their own conditions; Jobs
    prefer their Failed condition (DeadlineExceeded, BackoffLimitExceeded) and pick up pod issues
    while running. Flux rows use `flock_flux::failing_condition` (Stalled, then Helm Released,
    then Ready, including a remembered failure through retries); a reconciling object hides its
    last failure. Inspectors (resources, pods, nodes) and the Flux object page show What's wrong,
    then Conditions (type, status, age, with reason and message beneath so long reasons never
    break mid-word), then the object's events, then the rest; YAML stays last. Default inspector
    widths are theme constants per kind (`INSPECTOR_WORKLOAD` 560px for the five workload kinds
    including Jobs and CronJobs, `INSPECTOR_RESOURCE` 480px, `INSPECTOR_NODE` 420px,
    `INSPECTOR_POD` 360px so the pod list keeps its row actions in view); a dragged width is still
    remembered per inspector and wins. A reveal into another namespace keeps the inspector open
    until the namespace preference round-trips. Loco lists and the workload page are unchanged.
38. **Menu-bar health** (#233; amends 17 and 27; menu v2 per `design/screens/MenuBar.dc.html` and
    `MenuExtra.dc.html`): macOS shows a status item by default, built from the shared Store's
    snapshots: the sheep template icon with an error badge (`✕3`), else a warning badge (`▲6`),
    else none, dimmed when no cluster is reachable. A cluster in an error or warning state without
    counted problems (auth expired, degraded) adds one to its badge. The menu lists every cluster
    in snapshot order with its glyph and, on the right, its problem counts (`✕2 ▲3`) or, when it has
    none and is not healthy, its lowercased state (`auth expired`, `offline`). Choosing a cluster
    opens its overview as a tab in the frontmost Flock window (focusing an existing tab at that
    location) and brings it to the front; with no window it opens a new one. Open Flock (⌘O)
    brings the frontmost window forward or opens one; Pause notifications sets
    `notifications.paused` in `AppSettings`, silencing desktop notifications until Resume
    notifications; problems first seen while paused are not announced on resume. Quit Flock (⌘Q)
    exits regardless of windows. The problems list and Settings… left the menu.
    Settings → Appearance → Show in menu bar is persisted in `AppSettings`. Enabled, closing the last
    window (its close button, ⌘⇧W, or closing its last tab per 23) keeps Flock and its backend
    running in the menu bar and drops that window's saved tabs, so reopening does not bring back a
    window the user closed; disabled, the last window closing quits and keeps its tabs for the next
