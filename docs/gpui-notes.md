# gpui notes

What P0 learned about `gpui-pre` 0.3.9 and `gpui-component` 0.7.3. Sources live in
`~/.cargo/registry/src/*/gpui-pre-0.3.9` (examples in `examples/`) and `gpui-component-0.7.3/src`.

## Crates

- `gpui` = `gpui-pre` (renamed in `[workspace.dependencies]`).
- `gpui-platform` = `gpui-pre-platform`. `gpui-pre` has no platform of its own; the app is started with
  `gpui_platform::application()` (returns `gpui::Application`). Only `apps/flock` depends on it.
- Features on `gpui-pre-platform`: `runtime_shaders` is required unless full Xcode is installed (the
  build script otherwise runs `xcrun metal` and fails with "metal shader compilation failed").
  `font-kit` matches what upstream uses for its own tests.
- `gpui-component` (the styled kit) re-exports `gpui_base::Root`; `flock_ui::Root` re-exports it again so
  the app never names `gpui-component` directly. The umbrella `gpui-kit` crate exists but is not used.

## Startup

```rust
gpui_platform::application()
    .with_assets(flock_ui::assets::Assets)
    .run(|cx: &mut App| {
        flock_ui::init(forced_appearance, cx)?; // gpui_component::init + fonts + theme
        cx.bind_keys([KeyBinding::new("cmd-b", ToggleSidebar, None)]);
        cx.open_window(options, |window, cx| {
            let shell = cx.new(|cx| Shell::new(updates, commands, initial, window, cx));
            cx.new(|cx| Root::new(shell, window, cx))
        })?;
    });
```

- `gpui_component::init(cx)` must run before any component and before `Theme::change`.
- Every window's root view must be `Root` (overlays, menus, dialogs, notifications hang off it).
- `WindowOptions.titlebar = TitlebarOptions { title: None, appears_transparent: true,
  traffic_light_position: Some(point(TRAFFIC_LIGHT_X, TRAFFIC_LIGHT_Y)) }` gives the hidden titlebar with
  traffic lights in our 32px title row. gpui sizes the titlebar container to the button height plus
  twice `y`, so `y = (TITLE_ROW - 14) / 2` centres the 14px buttons; AppKit spaces them 9px apart, so
  they end 60px after `x`. The position is fixed for the window's life (`set_traffic_light_position`
  exists, but the layout keeps one row height so it never has to move). Dragging: `on_mouse_down(MouseButton::Left, |_, window, _| window.start_window_move())`
  on the strip and page header; buttons inside call `cx.stop_propagation()` on mouse down.
- Quit after the last window closes: check `cx.windows().is_empty()` in `on_window_closed`.
  Backend updates go through the shared `flock_ui::Store`; subscribe once per shell so receivers
  broadcast snapshots rather than competing for updates. The Store replays its latest snapshot
  when a window subscribes. Every pane owns a backend scope (`shell::pane::Scope`, an id from a process-wide
  counter): `Command::ForWindow(scope, command)` scopes backend navigation and detail watches, and
  `Command::WindowClosed(scope)` releases them when the pane closes, its window closes or the scope
  drops, while cluster connections and mutation actions remain shared. The shell keeps one
  `PaneScreens` (every screen entity, the load clock, the strip scroll) per model pane, matched by
  `tabs::PaneId` in `Shell::sync_panes`.
  Confirmation dialogs have separate focus and handlers per window; the Store publishes shared
  backend notices once so subscribers do not create duplicate toasts.

## Menu-bar verification

The pinned gpui exposes no status-item API. `apps/flock/src/menubar/native.rs` owns the AppKit
status item and menu on the main thread; action targets queue intents back into gpui. The menu-bar
model subscribes to the same Store as the windows, so monitoring continues with no windows open.

Headless coverage verifies snapshot labels, counts, severity ordering, bounded problem menus,
resource targets, settings persistence and the Settings toggle. Dark/light Settings shots cover
the in-app control. AppKit's actual status-item rendering, native menu interaction, activation and
process exit are not exercised by the headless platform and require a manual macOS check. Do not
launch the GUI or synthesize system input for automated verification.

## Fonts and assets

- Fonts: `cx.text_system().add_fonts(Vec<Cow<'static, [u8]>>)` with `include_bytes!` TTFs, then
  `.font_family("IBM Plex Sans")`. Files are in `crates/flock-ui/assets/fonts` (OFL, `OFL.txt`).
- Icons: `svg().path("icons/chevron-left.svg").size(px(11.)).text_color(c)`. The path is resolved by
  the app's `AssetSource` (`flock_ui::assets::Assets`, a static table). The SVG is used as an alpha mask,
  so stroke colour comes from `text_color`. gpui-component's own `Icon`/`IconName` expects Lucide SVGs at
  `icons/<name>.svg`; our asset source does not serve them yet, so add the needed files (or chain
  `gpui-kit-assets`) before using kit components that draw icons.
- Status glyphs (● ▲ ✕ ◐ ‖ ○) use the bundled Flock Status family, generated by
  `mise run gen:glyphs`. Mixed labels override only the symbol ranges; text keeps its parent font.

## Theme

- Flock tokens: `flock_ui::theme::Palette` (every HANDOFF token, dark + light), read with
  `cx.palette()` (`ActiveTheme` trait). Sizes are `theme::*` constants; never use literals in screens.
- `theme::init` also pushes fonts, radius and the main colours into `gpui_component::Theme` via
  `Theme::change(mode, None, cx)` then `Theme::update(cx, |t| ...)` (use `update`, not `global_mut`, so
  the kit's tokens and base projection stay in sync). Restyle more kit fields there as screens need them.
- `theme::configure(&AppSettings)` sets the mode and the two highlights; the palette is
  `highlight::apply(Palette::for_appearance(..), ..)`, re-derived on every mode or highlight change.
- OS appearance: `cx.observe_window_appearance(window, |_, window, cx| theme::follow_window(window, cx))`
  in the root view; `window.appearance()` returns `WindowAppearance::{Light, VibrantLight, Dark, VibrantDark}`.
  `--appearance dark|light` sets `Theme.forced`, which wins over the OS.

## Views, state, async

- `Render::render(&mut self, window, cx: &mut Context<Self>) -> impl IntoElement`.
- Click handlers need an id: `div().id("x").on_click(cx.listener(|this, _ev, window, cx| ...))`.
  Element ids for lists: `ElementId::NamedInteger("cluster".into(), ix as u64)`.
- Backend updates: `cx.spawn(async move |this, cx| while let Ok(u) = rx.recv().await {
  this.update(cx, |view, cx| { ...; cx.notify() })?; })`, keep the `Task` in a field (dropping cancels).
- Closures that borrow `cx` (e.g. `cx.listener`) inside iterator chains: collect to `Vec<AnyElement>`
  first, or the borrow checker rejects the second `cx` use.
- Actions: `gpui::actions!(flock, [ToggleSidebar])`; handle with
  `.on_action(cx.listener(|this, _: &ToggleSidebar, window, cx| ...))` on the root div, which must
  `track_focus(&focus_handle)` and be focused (`window.focus(&handle, cx)`), otherwise key bindings
  never reach it.

## Layout and styling gaps

- Tailwind-like API: `.flex().flex_col().flex_1().min_h_0().w(px).h(px).px().gap().rounded()
  .border_b(px(1.)).border_color(c).bg(c).text_size(px).font_weight(FontWeight::SEMIBOLD).truncate()`.
  Scrolling containers need an id: `.id("x").overflow_y_scroll()`.
- No letter-spacing and no text rotation.
- No CSS grid; tables should be `uniform_list` rows of fixed-width flex cells.

## Animation

- `element.with_animation(id, Animation::new(dur).with_easing(ease_out_quint()), |el, t| el.w(...))`.
  The animation restarts when the id changes, so the shell bumps a generation counter per toggle and
  uses `ElementId::NamedInteger("sidebar", generation)`; generation 0 renders without animation.
  Content inside an animated width uses a fixed width and `overflow_hidden` so it clips instead of
  reflowing.

- Tab strip motion (`shell/tab_motion.rs`): new tabs wrap in a clipped `max_w(TAB_GROW_MAX * t)` slot with
  fading opacity (natural width is unknown, so a cap stands in); closed tabs stay as view-only ghosts
  that shrink the same way and are dropped by a timer, never delaying the model; a reordered tab slides
  in from its old side under a per-move animation id. `with_animation` clocks use wall time, so Ui tests
  call `Ui::advance_clock`, which also sleeps and redraws. Reduce Motion skips ghosts and wrappers.
- An animation's progress is element state keyed by the whole element path, not just its id. Splitting
  a pane wraps it in `Split`, so every element inside gets a new path and any `with_animation` still
  in the tree starts again from frame 0. The view that owns a motion therefore clears it with a timer
  once it has played (`StripMotion::finish`, `kit::Entrance`, `DockState`, table flashes), and elements
  at rest render without `with_animation`. Inspectors take a `kit::Motion` from `Presence::track` or
  `Entrance::track` (keyed by the shown object) instead of an id string.

## Headless rendering and UI tests

`apps/flock-shots` renders Flock without any window, so nothing takes focus. It is dev-only: the
shipped `flock` binary never links it (`mise run bundle:loco` builds `-p flock` only).

- `gpui` and `gpui-platform` are used with `test-support`. `HeadlessAppContext::with_platform(text, assets,
  gpui_platform::current_headless_renderer)` runs on `TestPlatform` (no NSApplication, no NSWindow) with
  the real `gpui_apple::AppleTextSystem` (CoreText, the same shaper and rasterizer the app uses) and
  `MetalHeadlessRenderer`, which draws the scene into an offscreen Metal texture.
  `capture_screenshot(window)` returns an `RgbaImage`. Test windows default to scale 2, so 1440×900 gives
  2880×1800.
- `MacPlatform::new` needs the main thread, so the text system is built directly from `gpui-pre-apple`
  (`font-kit`) instead of `current_platform(true).text_system()`; that keeps it usable in nextest threads.
- Test mode draws dirty windows on every effect flush. Timers run on the `TestDispatcher` clock, so toasts
  never time out; the demo backend runs on real threads, so `settle` pumps `run_until_parked` until
  `Shell::settled()` (snapshot received, startup commands run) and then for a short quiet period.
  `cx.set_reduce_motion(true)` puts every `with_animation` at its final frame.
- Interaction tests use `TestAppContext::build_with_text_system` + `VisualTestContext`, because only
  `VisualTestContext::debug_bounds` can read `.debug_selector(..)` bounds (recorded only in debug builds
  with `test-support`). Its `TestPlatform` has no renderer, so `Ui::save_png` replays the recorded steps
  (keys, text, clicks at the same coordinates) in a `HeadlessAppContext` and captures that.
- Input goes through public `Window::dispatch_keystroke` / `Window::dispatch_event`; `Keystroke::parse`
  per character types text (space is `space`).
- Fidelity: glyphs, colours and layout match the windowed app. What differs: no traffic lights,
  no rounded window corners or shadow (the old `screencapture -l` included the window frame), and the
  appearance is always forced, never read from the OS.

## Tabs

- The tab strip (`shell/tabs.rs`) uses gpui drag and drop: `on_drag(DraggedTab, ..)` builds the
  preview view, every tab and the trailing filler take `on_drop::<DraggedTab>`. The Ui helper's
  `drag` (down, one move past `DRAG_THRESHOLD`, up) is enough to trigger it.
- `on_click` only fires for the left button; middle clicks arrive through `on_aux_click`
  (`ClickEvent::is_middle_click`), and right clicks too, so aux handlers check the button.
- ⌘-click opens in a new tab without plumbing through every screen: the shell root
  `capture_any_mouse_down` records whether the press had ⌘ or was the middle button, and the next
  navigation command dispatched from that click is wrapped in `Command::NewTab`. A key press
  clears it. Tables emit `Opened` for ⌘-clicks and middle clicks so row opens reach the shell.
- ⌘↵ inside a `TextField` never reaches a parent key context: the input binds `secondary-enter`
  itself, so the palette reads `InputEvent::PressEnter { secondary: true }`.
- `ScrollHandle::scroll_to_item` on the strip runs only when the active tab changes, so wheel
  scrolling the strip is not undone on the next frame.

## Text selection

- gpui-base (pulled in by gpui-component, now a direct dependency) has window-wide text selection:
  `Root` mounts `TextSelectionLayer` and binds ⌘C (`Root` context) to copy
  `TextSelection::selected_text`. Participants are `TextSelectionHandle`s that register a hitbox and
  their `TextLayout`s every frame; `kit::Selectable` is ours.
- Participants between the anchor and the cursor in document order take part, so the order must be
  stable from frame to frame: `kit::selectable` numbers participants in paint order and resets the
  counter after each draw (`window.defer`). An order that grows across frames makes coverage flip
  and the window redraws forever.
- A `cx.stop_propagation()` in a bubble-phase mouse-down above text stops the layer from starting a
  selection (it registers first, so it runs last); modals no longer stop it.
- Copy text joins participants with newlines and drops blank ones; a block with several lines uses
  one participant and its own copy text so blank lines survive. Paint-time copy text is one frame
  behind a drag; `TextSelection::has_selection` is current.

## Lints

`clippy::pedantic` is on; `match_same_arms` is allowed because AGENTS.md wants one arm per meaning, and
`return_self_not_must_use` because builder methods are everywhere.

## History navigation input

The pinned gpui macOS adapter registers `swipeWithEvent:` in `window.rs`. In `events.rs`, an ended
`NSEventTypeSwipe` with positive horizontal delta becomes a Back `MouseButton::Navigate` mouse-down;
a negative delta becomes Forward. Mouse buttons 4/5 (native indices 3/4) use the same event. The
shell captures these events in the pane under the pointer, focuses that pane and walks its active
tab's history. Horizontal scroll-wheel input stays scrolling. Headless interaction tests dispatch
the translated navigation events; they do not synthesize native trackpad gestures.
